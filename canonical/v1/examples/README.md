# examples/ —— 从真实档案算出来的，不是手写的

## `mark-status-transition.json`

一条真实的标记，跨五份成链档案被观测了 **6 次**，产出 **2 条修订**。

电影《…》（`36838707`），2026-07-18 标了「想看」，2026-08-01 改成「看过」。整个迁移过程恰好落在两次抓取之间，被完整拍了下来——这也是 [IDENTITY.md](../../IDENTITY.md) 里身份规则的原始依据。

生成方式：读 `20260801`…`20260807` 五份档案的 WARC，逐条抽取、算摘要、按内容分组。**没有一个值是手写的。**

### 看三件事

**① 6 次观测压成了 2 条修订。**

```
wish  2026-07-18  无评分  「能上6分我觉得都是国产好片」   ← 1 次观测
done  2026-08-01  评分 4  「确实还不错，剧情挺有趣的…」   ← 5 次观测
```

后 5 次抓取看到的内容完全一样，所以没有产生 5 条噪音行，而是延长了同一条修订的 `last_observed_at` 并往 `observations` 里追加。「我们在 T 时刻看到它还是这样」照样可查，而且每一条都指回具体的 `capture_id`。

**② 逐字段摘要一眼就能看出边界在哪。**

两版之间：

```
变了     status · marked_at · rating · comment · tags
没变     raw_meta
```

变的五个全是**用户写的东西**，没变的那个是**作品目录数据**。整条算一个摘要的话，这个区别就没了——而它正是「用户内容与目录数据不能同表」那条规则的可见形式。

（也因此 `raw_meta` 严格说不属于标记。它留在这里只是作为「那一行当时长什么样」的观测记录，权威版本在 `subjects.ndjson`。）

**③ 那条 想看 短评在豆瓣上已经没有了。**

它被 看过 的短评覆盖了。这份档案是它仅存的两个地方之一——另一个是广播（发布后不可编辑，还带秒级时间戳 `2026-07-18 12:44:56`）。

这就是整个项目要买的东西：**不是"我标了什么"，而是"我当时说了什么"。**

### 还没有的

一个能跑的参考解析器，以及 `bundle/v1/tests/` 那样的反例套件。schema 目前只被结构性检查覆盖（能解析、`$ref` 不悬空）。
